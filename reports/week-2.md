- 반면 NFC 방식이 무조건 더 편할 것이라는 가설은 명확하게 지지되지 않았다.

### 5. 다음 액션 결정

- 다음 주에는 NFC 병행 출석 프로토타입 흐름을 설계하기로 했다.

- 인터뷰를 통해 출석 과정의 핵심 문제는 단순히 버튼을 누르는 행위가 아니라, 출석 화면이 안정적으로 뜨지 않는 과정이라는 점을 확인했다.
- NFC 방식은 가능성이 있지만, 병목 현상과 장소 제약을 함께 고려해야 한다는 점을 알게 되었다.

### 인터뷰를 통해 새로 발견한 문제

#### 1. 출석 여부 확인도 불편하다
- 단순히 출석을 찍는 과정뿐 아니라, 출석이 제대로 처리되었는지 확인하는 과정도 불편했다.
- 당일 출석 기록이 바로 보이지 않아 불편하다는 의견이 있었다.
- Woowanet에 연결되어야 출석 여부를 확인할 수 있어 불편하다는 의견이 있었다.
- 체크를 했는데 UI에 바로 반영되지 않아 다시 들어가 확인해야 한다는 의견이 있었다.

#### 2. 하교 체크는 알림만으로 해결되지 않는다
- 일부 사용자는 하교 체크를 놓친 경험이 있었다.
- 알림을 봤지만 실제 행동으로 이어지지 않아 출석을 놓친 경험이 있었다.
- 알림만으로는 하교 체크 누락 문제를 완전히 해결하기 어렵다고 판단했다.

#### 3. NFC는 편리함과 장소 제약을 동시에 가진다
- NFC는 태그 방식이기 때문에 빠를 수 있다.
- 반대로 특정 위치에 가서 찍어야 한다는 제약이 있다.
- 사람이 몰릴 경우 현재 앱 방식보다 오히려 오래 걸릴 수 있다는 우려가 있었다.
- NFC 기기 고장이나 혼잡 상황에 대비할 대체 수단이 필요하다고 판단했다.

    - NFC 태그 후 출석 성공/실패 화면을 설계한다.
    - NFC 기기 배치 시나리오를 정리한다.
    - 사용자에게 해당 흐름이 기존 방식보다 더 빠르고 안정적으로 느껴지는지 확인한다.

## D. 회고

### 깨진 가설
- 깨진 가설:
    - NFC 방식은 현재 출석 방식보다 더 간단한 방식으로 인식된다.

- 처음 예상:
    - NFC를 태그하는 방식이기 때문에 기존 앱 실행 → 와이파이 연결 → 출석 화면 진입 → 버튼 클릭 과정보다 더 간단하게 느껴질 것이라고 예상했다.

- 실제 결과:
    - NFC 방식이 더 편할 것 같다는 의견이 있었다.
    - 하지만 NFC만 단독으로 운영할 경우 병목 현상이 생길 수 있다는 우려도 함께 나타났다.
    - 특정 위치에 가서 찍어야 하는 장소 제약도 함께 언급되었다.
    - 기존 앱이 안정적으로 고쳐진다면 현재 방식이 더 편할 수 있다는 의견도 있었다.

- 받아들인 점:
    - NFC 방식은 기존 출석 방식을 완전히 대체하기보다 기존 앱 방식과 병행하는 형태가 더 적절하다고 판단했다.
    - 핵심 과제는 NFC 자체 구현보다 병목 현상을 줄이는 방식이라고 판단했다.
    - 출석 방식의 목표를 “완전 대체”가 아니라 “불안정한 상황에서 사용할 수 있는 보조 수단”으로 수정했다.

### 인터뷰에서 못 잡은 것
- NFC 기기가 몇 개 정도 배치되어야 병목이 줄어들 수 있는지 충분히 확인하지 못했다.
- 사용자가 실제로 어느 위치에서 NFC를 찍는 것이 편하다고 느끼는지 확인하지 못했다.
- NFC 방식에서 출석 성공/실패 피드백이 어느 정도로 명확해야 안심할 수 있는지 확인하지 못했다.
- 기존 앱 방식과 NFC 방식이 함께 있을 때 사용자가 어떤 기준으로 방식을 선택할지 확인하지 못했다.
- 출석 여부 확인 화면이 어떻게 개선되면 사용자가 충분히 신뢰할 수 있을지 확인하지 못했다.

### 다음 인터뷰를 위한 액션
- NFC 방식 자체에 대한 선호만 묻지 않는다.
- 실제 등교 상황을 가정한 구체적인 흐름을 보여준다.
- NFC 병행 출석 흐름을 시나리오나 간단한 화면 형태로 보여준다.
- 사용자가 어느 지점에서 불편하거나 불안한지 확인한다.
- 병목 현상과 장소 제약에 대한 반응을 더 구체적으로 확인한다.
