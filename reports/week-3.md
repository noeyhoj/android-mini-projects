# Week 3 보고서 - Bello

## 이번 주 한 일 (계획 vs 실제)

### 1. NFC 출석 MVP 개발

지난주 인터뷰 결과를 바탕으로 NFC 출석 MVP 개발을 진행했다.
NFC를 기존 출석 앱의 완전한 대체재가 아니라, 기존 방식과 병행할 수 있는 보완 수단으로 보기로 했다.
Android 기준으로 NFC 태그를 인식하고 출석/퇴실 기록을 저장하는 흐름을 구현했다.
실제 출석 시스템 연동보다는 Firebase Realtime Database를 활용한 테스트용 MVP 구현에 집중했다.

### 2. 실제 사용자 테스트 진행

6/8~6/10 동안 5명의 테스터가 실제 등교/퇴실 상황에서 NFC 출석 MVP를 사용했다.
테스트를 통해 NFC 태그를 찍는 흐름이 실제 출석 상황에서 자연스럽게 받아들여지는지 확인했다.
또한 기존 앱 방식에서 불편했던 와이파이 연결 대기, 로딩 실패, 앱 재실행 문제가 NFC 방식으로 줄어드는지도 함께 확인했다.

### 3. 테스트 결과 인터뷰 및 개선점 정리

6/11에는 테스트 참여자를 대상으로 인터뷰를 진행해 NFC 방식의 장점과 불편함을 정리했다.
테스트 결과, NFC 방식은 기존 앱의 와이파이 연결 대기, 로딩 실패, 앱 재실행 문제를 줄일 수 있다는 점에서 긍정적으로 평가되었다.
5명 중 4명이 기존 앱보다 NFC 방식을 더 선호했다.
다만 앱을 반드시 켜야 하는 점, 태그 위치까지 이동해야 하는 점, 태그 후 결과 확인이 불명확한 점은 새로운 불편으로 확인되었다.

### 결론

전반적으로 인터뷰 결과 반영 → MVP 개발 → 실제 사용자 테스트 → 인터뷰 분석 흐름에 맞춰 진행했다.
이번 테스트를 통해 NFC 방식이 기존 출석 앱의 불편을 줄일 가능성이 있다는 점을 확인했다.
하지만 NFC 방식도 새로운 불편을 만들 수 있기 때문에, 기존 출석 앱을 완전히 대체하기보다는 병행 가능한 보완 수단으로 제공하는 것이 더 적절하다고 판단했다.

### 이번 주에 만든 핵심 기능

1. Android 기반 NFC 태그 인식 흐름

    * 앱 실행 상태에서 NFC 태그를 인식한다.
    * 태그의 `tagId`를 추출한다.
    * 실제 테스트에서 사용자가 태그를 찍으면 출석/퇴실 기록이 저장되도록 했다.

2. Firebase Realtime Database 연동

    * 출석/퇴실 기록을 Firebase에 저장한다.
    * 테스트용 MVP이므로 실제 우테코 출석 API는 사용하지 않는다.
    * 테스트 기간 동안 사용자별 출석/퇴실 기록을 확인할 수 있도록 했다.

3. 사용자 번호 기반 임시 로그인

    * 간단한 MVP 구현이 목적이었기 때문에, 로그인 기능보다는 사용자를 구분하는 정도가 적절하다고 판단했다.
    * Firebase Auth는 사용하지 않고, 사용자가 입력한 번호를 기준으로 임시 로그인처럼 사용했다.

4. 출석 상태 확인 흐름

    * NFC 태그 후 출석 성공 여부를 보여준다.
    * 출석 또는 퇴실 시간을 바로 확인할 수 있도록 한다.
    * 출석 규칙에 맞춰 조퇴, 결석 등 상태도 나타낼 수 있도록 했다.
    * 테스트 결과, 사용자는 단순히 태그 인식 여부보다 출석/퇴실이 정상 처리되었는지 확인하는 것을 더 중요하게 생각한다는 점을 확인했다.

## C. 의사결정 / 막힘

### 새로 발견한 문제

* 실제 테스트 결과, NFC 방식은 출석 처리 자체는 빠르게 느껴졌지만 앱 실행, 태그 위치 이동, 결과 확인 측면에서 새로운 불편도 만들 수 있음을 확인했다.
* NFC 방식은 빠를 수 있지만, 특정 위치에 가서 찍어야 하는 제약이 있다.
* 기존 출석 앱은 와이파이가 연결된 공간이라면 어디서든 출석할 수 있지만, NFC는 태그 위치까지 이동해야 한다.
* 6/11 인터뷰에서 모든 참여자가 실제 도입 시 등교·퇴실 시간대 병목 가능성을 언급했다.
* 기존 출석 앱의 문제는 단순히 출석 버튼을 누르는 과정이 아니라, 출석 화면까지 안정적으로 진입하지 못하는 문제에 가깝다.
* 사용자는 출석을 찍는 것뿐 아니라, 출석이 제대로 되었는지 확인하는 것에도 불안감을 느끼고 있었다.
* NFC 태그 후 출석/퇴실이 정상 처리되었는지 즉시 알 수 있는 피드백이 부족하면, 기존 앱과 비슷한 불안감을 줄 수 있다.
* 히스토리 화면은 단순 기록 목록이 아니라, 하루 단위로 출석 상태를 판단할 수 있는 화면이어야 한다.

### 결정 + 근거

#### 결정 A

* NFC를 기존 출석 앱의 완전한 대체재가 아니라, 기존 방식과 병행 가능한 보조 수단으로 설계한다.

#### 근거

* 6/8~6/10 테스트 결과, 5명 중 4명이 NFC 방식을 선호했다.
* 긍정 이유는 기존 앱의 와이파이 연결 대기, 로딩 실패, 앱 재실행 문제를 줄일 수 있다는 점이었다.
* 하지만 NFC에 대한 반응이 모두 긍정적이지만은 않았다.
* 기존 앱 방식은 와이파이가 연결되어 있을 때 캠퍼스 내 어디서든 출석할 수 있다는 장점이 있다.
* NFC 방식은 태그 위치 이동과 병목이라는 새로운 문제가 생길 수 있다.
* 따라서 NFC를 기존 앱의 완전한 대체재로 보기보다는, 기존 방식의 불안정함을 보완하는 선택지로 제공하는 것이 적절하다고 판단했다.

#### 결정 B

* Firebase Auth 없이 사용자 번호 기반 임시 로그인과 Realtime Database를 사용한다.

#### 근거

* 이번 검증에는 복잡한 인증 구조보다 빠르게 테스트 가능한 흐름이 더 중요하다.
* 서버를 직접 만드는 것보다 Realtime Database가 빠르게 구현할 수 있어서 MVP에 적합하다고 판단했다.
* 운영 수준의 보안보다 사용 경험 검증을 우선했다.
* 실제 테스트에서는 사용자 번호만으로도 출석/퇴실 기록을 구분하는 데 충분했다.

#### 결정 C

* 다음 개선 방향은 기능 추가보다 “출석 처리 확인 경험”을 명확하게 만드는 데 집중한다.

#### 근거

* 인터뷰 결과, 사용자는 NFC 태그가 인식되었는지보다 출석/퇴실이 정상 처리되었는지를 더 중요하게 생각했다.
* 태그 후 성공/실패 여부, 오늘 출석 상태, 마지막 태그 시간이 명확히 보여야 한다는 의견이 있었다.
* 히스토리 화면에서도 단순 로그보다 하루 단위 출석 상태 요약이 필요하다는 의견이 많았다.

* AI는 기술적 제약과 구현 방향을 정리하는 보조 역할을 했고, 최종 결정은 팀이 MVP 목적과 테스트 결과에 맞춰 판단했다.

* NFC를 도입하면 기존 출석 방식의 불편함이 줄어들 것이다.
* 테스트 결과 이 가정은 일부 지지되었지만, 완전히 검증되었다고 보기는 어렵다.
* NFC는 기존 앱의 불확실한 대기 시간을 줄일 수 있지만, 태그 위치 이동과 병목이라는 새로운 문제가 생길 수 있다.
* NFC 자체가 해결책이라고 단정하기보다는, 어떤 위치에 어떻게 배치하고 어떤 피드백을 제공해야 문제 해결로 이어지는지 추가 검증이 필요하다.

### 다음에 개선할 것

* 태그 후 당일 출석/퇴실 성공 여부를 홈화면에서 지속적으로 보여준다.
* 출석 화면에서 오늘의 출석 상태와 마지막 태그 시간을 바로 확인할 수 있도록 한다.
* 히스토리 화면을 단순 로그 목록이 아니라 하루 단위 출석 상태 요약 화면으로 개선한다.
* NFC 태그 위치를 사용자의 생활 동선과 연결해 배치하는 방안을 고민한다.
* 병목을 줄이기 위해 태그를 층별·마을별·동선별로 분산 배치하는 방안을 검토한다.
* 앱 실행 없이 태그할 수 있는 흐름이 가능한지 Android 기준으로 추가 검토한다.
* NFC 인식 위치, 사용 방법, 보안 안내를 앱 안에서 더 구체적으로 제공한다.
* Android MVP 결과를 바탕으로 iOS에서도 NFC 출석 흐름을 구현할 수 있는지 추가로 검토하고, 가능하다면 iOS 버전 개발도 진행한다.

### 최종 발표 흐름 초안

* 기존 출석 앱의 와이파이·로딩 문제를 보완하기 위해 NFC 출석 MVP를 개발하고, 6/8~6/10 실제 테스트와 6/11 인터뷰를 통해 NFC 방식의 장점과 한계, 다음 개선 방향을 확인했다.

## E. MVP 테스트 및 인터뷰 결과

### 테스트 진행 개요

이번 주에는 NFC 출석 MVP를 실제 사용자에게 전달해 사용 경험을 확인했다.

* 테스트 인원: 5명
* 테스트 기간: 3일
* 테스트 방식: 실제 등교/퇴실 상황에서 NFC 출석 앱 사용
* 인터뷰 진행: 테스트 종료 후 목요일에 인터뷰 진행
* 목적: NFC 방식이 기존 출석 앱의 불편함을 줄일 수 있는지, 그리고 새롭게 생기는 불편함은 무엇인지 확인

### 종합 결과

| 항목        | 결과                                                    |
| --------- | ----------------------------------------------------- |
| NFC 방식 선호 | 5명 중 4명                                               |
| 기존 앱 선호   | 5명 중 1명                                               |
| 공통 긍정 요인  | 기존 앱의 와이파이 연결 문제, 로딩 지연, 앱 재실행 문제를 줄일 수 있음            |
| 공통 부정 요인  | 앱을 켜야 함, 태그 위치까지 이동해야 함, 태그 위치가 잘 보이지 않음, 결과 확인이 불명확함 |

테스트 결과, NFC 방식은 기존 출석 앱의 가장 큰 불편이었던 **와이파이 연결 대기, 로딩 실패, 앱 재실행 문제**를 줄일 수 있다는 점에서 긍정적으로 평가되었다.

다만 NFC 방식이 무조건 더 편한 것은 아니었다. 사용자는 NFC라면 앱을 켜지 않고 바로 태그하는 방식을 기대했지만, 현재 MVP에서는 앱 실행 후 태그해야 했기 때문에 일부 기대와 차이가 있었다. 또한 태그 위치까지 직접 이동해야 한다는 점은 기존 앱에는 없던 새로운 불편으로 드러났다.

### 주요 긍정 경험

| 긍정 요소            | 언급 인터뷰이                        | 내용                                        |
| ---------------- | ------------------------------ | ----------------------------------------- |
| 출석 처리 속도가 빠름     | 인터뷰이 A, 인터뷰이 C, 인터뷰이 D, 인터뷰이 E | 태그를 찍으면 출석/퇴실이 바로 처리되어 기존 앱보다 빠르게 느껴짐     |
| 와이파이 문제를 줄일 수 있음 | 인터뷰이 A, 인터뷰이 D, 인터뷰이 E         | 기존 앱의 와이파이 연결 대기, 로딩 실패, 재실행 문제가 줄어듦      |
| 사용 흐름이 단순함       | 인터뷰이 B, 인터뷰이 D, 인터뷰이 E         | 앱 진입 후 태그만 하면 되어 버튼을 찾거나 여러 단계를 거치지 않아도 됨 |
| 출석을 까먹을 가능성 감소   | 인터뷰이 B                         | 태그 행동이 습관화되면 출석 행위 자체를 자연스럽게 떠올릴 수 있음     |
| 기록 확인이 기존보다 빠름   | 인터뷰이 E                         | 히스토리 탭에서 출석/퇴실 기록을 비교적 빠르게 확인할 수 있음       |

NFC 방식의 가장 큰 장점은 **출석 처리 자체가 빠르고 단순하게 느껴진다는 점**이었다.

기존 앱에서는 와이파이 연결 여부를 기다리거나, 로딩이 끝나지 않아 앱을 재실행해야 하는 상황이 있었다. 반면 NFC 방식은 태그가 정상적으로 인식되면 바로 출석/퇴실 처리가 가능했기 때문에, 사용자가 통제하기 어려운 대기 시간이 줄어든다는 장점이 있었다.

### 주요 불편 경험

| 불편 요소             | 언급 인터뷰이                                | 내용                                              |
| ----------------- | -------------------------------------- | ----------------------------------------------- |
| 앱을 반드시 켜야 함       | 인터뷰이 A, 인터뷰이 B, 인터뷰이 D, 인터뷰이 E         | NFC라면 앱을 켜지 않고 찍는 방식을 기대했지만, 현재는 앱 실행이 필요함      |

| 병목 가능성            | 전원                                     | 출석/퇴실 시간대에 사람이 몰리면 줄이 생길 수 있음                   |

불편 경험을 통해 확인한 점은, NFC 방식의 핵심은 단순히 태그를 읽는 기술 구현이 아니라 **태그 전후의 사용자 흐름을 얼마나 명확하게 설계하느냐**라는 점이었다.

사용자는 태그가 인식되었는지보다 **출석이 정상적으로 처리되었는지**를 더 중요하게 생각했다. 따라서 성공/실패 여부, 출석/퇴실 상태, 마지막 태그 시간을 즉시 보여주는 피드백이 필요하다는 것을 확인했다.

태그 위치는 단순한 설치 장소 문제가 아니라 NFC 방식의 사용성을 결정하는 핵심 요소였다.

기존 앱은 와이파이가 연결된 공간이라면 어디서든 출석할 수 있지만, NFC 방식은 특정 위치까지 이동해야 한다. 따라서 태그 위치가 사용자의 생활 동선과 맞지 않으면 기존 앱보다 오히려 불편하게 느껴질 수 있다.

| 추가 고려    | 태그 개수를 늘리면 병목은 줄지만, 훼손/유실/관리 부담이 증가함 |

모든 인터뷰이가 병목 가능성을 언급했다.

다만 병목 문제는 NFC 방식 자체의 실패라기보다는, 태그를 어디에 몇 개 설치하느냐에 따라 달라질 수 있는 운영상의 문제로 보였다. 한 지점에만 태그를 설치하기보다는 층별, 마을별, 주요 동선별로 분산 배치하는 방식이 필요하다.

### 개선 우선순위

| 우선순위 | 개선 방향                         | 근거                                               |
| ---- | ----------------------------- | ------------------------------------------------ |
| 1    | **태그 후 출석/퇴실 성공 여부를 즉시 알려주기** | 여러 인터뷰이가 태그 후 정상 처리 여부를 확신하기 어렵다고 언급함            |
| 2    | **오늘 출석 상태를 출석 화면에서 바로 보여주기** | 인터뷰이 A가 가장 큰 불편으로 언급, 인터뷰이 C도 하루 단위 상태 판단 필요성 제기 |
| 3    | **히스토리 화면을 하루 단위로 정리하기**      | 인터뷰이 A, B, D, E 모두 기록 확인 UI 개선 필요성을 언급함          |
| 4    | **NFC 태그 위치와 설치 형태 개선하기**     | 태그가 눈에 잘 안 보이거나, 벽에 붙은 방식이 직관적이지 않다는 의견 다수       |
| 5    | **태그를 생활 동선에 맞게 분산 배치하기**     | 병목 완화와 태그를 까먹는 문제 해결에 필요                         |
| 6    | **앱 실행 없이 태그 가능한 흐름 검토하기**    | NFC의 장점을 살리기 위해 앱 실행 단계를 줄여야 한다는 의견 다수           |
| 7    | **자동 새로고침 적용하기**              | 최신 기록이 바로 반영되지 않아 사용자가 직접 확인해야 하는 불편이 있음         |
| 8    | **상태 세분화 및 누적 정보 제공하기**       | 단순 출석/퇴실 기록보다 하루 기준 최종 상태, 월별 점수 등이 필요하다는 의견     |
| 9    | **NFC 사용 안내 및 보안 안내 추가하기**    | NFC 위치, 켜는 방법, 보안 우려에 대한 설명 필요                   |

### 최종 인사이트

#### 핵심 인사이트 1. NFC 방식은 기존 앱의 “불확실한 대기 시간”을 줄여준다

기존 앱의 가장 큰 문제는 와이파이 연결, 로딩, 앱 재실행처럼 사용자가 통제하기 어려운 대기 시간이었다. NFC 방식은 태그만 정상적으로 되면 바로 출석 처리가 가능하다는 점에서 긍정적으로 평가되었다.

#### 핵심 인사이트 2. 하지만 NFC의 장점은 “앱 실행 과정” 때문에 일부 약해졌다

대부분의 인터뷰이는 NFC라면 앱을 켜지 않고 찍는 방식을 기대했다. 현재처럼 앱을 직접 열고 태그해야 한다면 기존 앱과 사용 단계가 크게 다르지 않다고 느낄 수 있다.

#### 핵심 인사이트 3. 태그 위치는 단순 설치 문제가 아니라 사용성의 핵심이다

NFC 방식은 사용자가 태그 위치까지 이동해야 하므로, 태그 위치가 생활 동선과 맞지 않으면 기존 앱보다 불편해질 수 있다. 특히 인터뷰이 C는 이 이유로 현재 상태에서는 기존 앱을 더 선호한다고 응답했다.

#### 핵심 인사이트 4. “찍었는지”보다 “정상 처리되었는지”를 알려주는 것이 중요하다

사용자는 진동이나 태그 인식만으로 출석이 완료되었다고 확신하기 어렵다. 따라서 성공/실패 여부, 출석/퇴실 상태, 마지막 태그 시간을 즉시 보여주는 피드백이 필요하다.

#### 핵심 인사이트 5. 기록 화면은 단순 로그가 아니라 출석 상태 판단 화면이어야 한다

사용자들은 단순히 태그 기록만 보고 싶은 것이 아니라, 오늘 출석이 정상인지, 퇴실했는지, 결석인지, 지각/조퇴 상태인지, 누적 점수는 어떤지를 알고 싶어 했다. 따라서 히스토리는 로그 목록이 아니라 **하루 단위 출석 상태 요약 화면**에 가까워져야 한다.

---

### 테스트 결과 한 줄 정리

> NFC 출석 방식은 기존 앱의 와이파이·로딩 문제를 줄일 수 있어 전반적으로 긍정적이지만, 실제 도입을 위해서는 태그 후 즉시 피드백, 오늘 상태 표시, 하루 단위 히스토리, 생활 동선에 맞춘 태그 배치, 앱 실행 단계를 줄이는 개선이 우선 필요하다.
